# บันทึกการแก้โจทย์

ไฟล์นี้ต้องเขียนโดยนักศึกษาด้วยคำพูดของตนเอง

ใช้ template นี้เฉพาะกับโจทย์ OJ ที่ถูกระบุว่าต้องส่ง learning log เท่านั้น

ห้ามให้ AI เขียนไฟล์นี้แทนคุณ AI อาจช่วยตรวจ grammar, formatting หรือความชัดเจนได้ หลังจากที่คุณเขียนเนื้อหาของตนเองแล้ว

ถ้าใช้ AI กับโจทย์ learning-log-required นี้ ต้องทำไฟล์ `ai_reflection.md` ด้วย

## 1. ข้อมูล OJ

หมายเลข/ชื่อโจทย์ OJ:

```text
OJ3477 - [LEARNING LOGS] Pad Thai
```

OJ submission ID ถ้ามีการส่งแล้ว:

```text
680628
```

สถานะ OJ:

```text
Pass
```

เวลาที่ใช้คิดและทำโจทย์ด้วยตนเอง:

```text
15-30 minutes
```

เลือกหนึ่งข้อ:

```text
0-15 minutes
15-30 minutes
30-60 minutes
1-3 hours
3-6 hours
6-24 hours
1-3 days
4-7 days
1-4 weeks
More than 4 weeks
```

วิธีนับเวลา:

- นับเฉพาะเวลาที่ตั้งใจทำโจทย์นี้ด้วยตนเองจริง ๆ
- เริ่มนับตั้งแต่ตอนที่อ่านโจทย์ครั้งแรก
- ไม่นับเวลาพัก กินข้าว เรียน นอน เวลาที่ทำโจทย์อื่น หรือเวลาที่ไม่ได้ทำโจทย์นี้
- ถ้าใช้ AI ให้นับเฉพาะเวลาที่ทำด้วยตนเองก่อน prompt แรกที่ถาม AI
- ถ้าถามเพื่อน TA หรือผู้สอน ให้นับเฉพาะเวลาที่ทำด้วยตนเองก่อนขอความช่วยเหลือครั้งแรก
- ถ้าใช้ทั้ง AI และความช่วยเหลือจากคน ให้นับเฉพาะเวลาที่ทำด้วยตนเองก่อนขอความช่วยเหลือจากภายนอกครั้งแรก ไม่ว่าจะเป็น AI หรือคน
- ถ้าไม่ได้ใช้ AI และไม่ได้ขอความช่วยเหลือจากคน ให้นับเวลาถึงก่อนเขียน `submission.md`
- ประมาณเวลาได้ แต่ต้องซื่อสัตย์

## 2. ความเข้าใจโจทย์ของฉัน

เขียนโจทย์ด้วยคำพูดของตนเอง

ให้อธิบาย input, output และ constraints สำคัญด้วย

ถ้ายังไม่เข้าใจโจทย์ทั้งหมด ให้เขียนสิ่งที่เข้าใจในตอนนี้ ความเข้าใจอาจยังไม่ครบหรืออาจผิดได้ แต่ต้องพยายามอธิบายอย่างจริงใจ

```text
โจทย์ให้ตรวจสอบการทำผัดไทยตามสูตรของเชฟ โดยแบ่งการรับข้อมูลเป็น 2 ช่วง ช่วงแรกรับรายการวัตถุดิบเข้ามาทีละบรรทัดจนกว่าจะพบคำว่า "Cook" และช่วงที่สองรับรสชาติต่างๆ เข้ามาทีละบรรทัดจนกว่าจะพบคำว่า "End" จากนั้นนำมาประเมินผลตามลำดับเงื่อนไข:
1. หากมีวัตถุดิบนอกเหนือจาก 11 ชนิดที่กำหนดไว้ ให้ตอบ "This is not Pad Thai!!!"
2. หากใช้วัตถุดิบไม่ครบทั้ง 11 ชนิด ให้ตอบ "This is bad!"
3. หากวัตถุดิบครบทั้ง 11 ชนิด และมีรสชาติครบ 3 รสคือ Sweet, Sour, Salty โดยไม่มีรสอื่นปน ให้ตอบ "Delicious!"
4. หากวัตถุดิบครบแต่รสชาติไม่ครบ 3 รส หรือมีรสชาติอื่นเกินมา ให้ตอบ "Not Bad..."

Input:
หลายบรรทัดแรก: รายชื่อวัตถุดิบทีละบรรทัด สิ้นสุดเมื่อเจอคำว่า "Cook"
หลายบรรทัดต่อมา: รายชื่อรสชาติทีละบรรทัด สิ้นสุดเมื่อเจอคำว่า "End"

Output:
แสดงข้อความประเมินของเชฟ 1 บรรทัด ("Delicious!", "Not Bad...", "This is bad!" หรือ "This is not Pad Thai!!!")

Constraints:
วัตถุดิบที่ถูกต้องมี 11 ชนิดตามที่โจทย์ระบุ
รสชาติที่ถูกต้องมี 3 รสชาติคือ Sweet, Sour, Salty
ตัวสะกดและตัวพิมพ์เล็ก-ใหญ่ต้องตรงตามที่กำหนด
```

## 3. แผนแรกของฉัน

เขียนแผนแรกก่อนรับความช่วยเหลือจาก AI เพื่อน TA ผู้สอน หรือก่อนสรุป code สุดท้าย

ถ้าใช้ AI ให้เขียนแผนที่มีอยู่ก่อน prompt แรกที่ถาม AI

ถ้าถามเพื่อน TA หรือผู้สอน ให้เขียนแผนที่มีอยู่ก่อนถาม

ถ้าไม่ได้ใช้ AI และไม่ได้ขอความช่วยเหลือจากคน ให้เขียนแผนที่มีอยู่ก่อนหรือระหว่างเริ่มเขียน code

แผนนี้เขียนแบบคร่าว ๆ ได้ อาจยังไม่สมบูรณ์หรืออาจต่างจากวิธีสุดท้าย

สามารถเขียนเป็น pseudocode, flowchart idea หรือขั้นตอนความคิดได้

```text
Step 1: สร้างเซต valid_ingredients บันทึกวัตถุดิบที่ถูกต้องทั้ง 11 ชนิด และสร้างเซต valid_tastes บันทึกรสชาติทั้ง 3 รส (Sweet, Sour, Salty)
Step 2: สร้างฟังก์ชัน collect_inputs(stop_token) โดยใช้ลูป while รับค่าทีละบรรทัดพร้อม .strip() และเก็บลงในเซต จนกว่าจะเจอ stop_token แล้ว return เซตนั้นออกมา
Step 3: เรียก collect_inputs("Cook") เพื่อเก็บวัตถุดิบของผู้ใช้ไว้ใน user_ingredients
Step 4: เรียก collect_inputs("End") เพื่อเก็บรสชาติของผู้ใช้ไว้ใน user_tastes
Step 5: ตรวจสอบวัตถุดิบแปลกปลอม โดยเช็คว่า user_ingredients ไม่ได้เป็น subset ของ valid_ingredients หรือไม่ (not user_ingredients.issubset(valid_ingredients)) หากจริงให้พิมพ์ "This is not Pad Thai!!!"
Step 6: ตรวจสอบความครบถ้วนของวัตถุดิบ โดยเช็คว่า valid_ingredients เป็น subset ของ user_ingredients หรือไม่ หากไม่ครบให้พิมพ์ "This is bad!"
Step 7: ถ้าวัตถุดิบถูกต้องครบถ้วน ให้เปรียบเทียบเซตรสชาติ user_tastes == valid_tastes ถ้าเท่ากันพอดีให้พิมพ์ "Delicious!"
Step 8: หากรสชาติไม่เท่ากับ valid_tastes (รสไม่ครบ หรือมีรสแปลกปลอม) ให้พิมพ์ "Not Bad..."

ก่อนเริ่มเขียน ฉันคิดว่าจะเก็บข้อมูลเป็น list แล้ววนลูปนับจำนวนและตรวจสอบทีละรายการ แต่การใช้ set ช่วยกำจัดข้อมูลซ้ำซ้อน (เช่น ใส่ไข่ 2 ฟอง) ได้โดยอัตโนมัติ และฟังก์ชันเกี่ยวกับเซตอย่าง .issubset() กับการเปรียบเทียบ == ทำให้ตรวจสอบเงื่อนไขทั้งหมดได้สั้น กระชับ และแม่นยำ
```

## 4. วิธีสุดท้ายที่ใช้จริง

อธิบายสั้น ๆ ว่า algorithm หรือวิธีสุดท้ายที่ใช้จริงใน code ที่ส่งคืออะไร

หัวข้อนี้ต่างจาก Section 3:

- Section 3 คือแผนแรกก่อนใช้ AI ก่อนรับความช่วยเหลือจากคน หรือก่อนเขียน code สุดท้าย
- Section 4 คือวิธีสุดท้ายที่ใช้ใน solution จริง
- ถ้าวิธีสุดท้ายเหมือนกับแผนแรก ให้เขียนว่าเหมือนกัน และอธิบายสั้น ๆ ว่าทำไม

ห้ามคัดลอกคำอธิบายจาก AI

ห้ามคัดลอกคำอธิบายจากคนอื่น

```text
วิธีสุดท้ายของฉันเหมือนกับแผนที่วางไว้ โดยสร้างฟังก์ชัน collect_inputs เพื่อรับข้อความและนำไปเก็บใน set จนกว่าจะเจอคำสั่งหยุด ("Cook" และ "End") ซึ่งช่วยตัดปัญหาเรื่องการใส่วัตถุดิบหรือรสชาติซ้ำกัน จากนั้นนำ user_ingredients และ user_tastes มาเปรียบเทียบกับ valid_ingredients และ valid_tastes ด้วยคำสั่ง if-elif-else ตามลำดับความสำคัญของเงื่อนไข เริ่มจากตรวจว่ามีวัตถุดิบนอกเหนือสูตรหรือไม่ด้วย not issubset() ถ้ามีจะพิมพ์ "This is not Pad Thai!!!" ถัดมาตรวจว่าวัตถุดิบครบไหมด้วย issubset() ถ้าไม่ครบพิมพ์ "This is bad!" และสุดท้ายตรวจรสชาติว่าตรงกับเซตรสชาติมาตรฐานเป๊ะหรือไม่ ถ้าใช่พิมพ์ "Delicious!" นอกนั้นพิมพ์ "Not Bad..." ซึ่งครอบคลุมทั้งกรณีวัตถุดิบขาด วัตถุดิบเกิน และรสชาติไม่ตรงตามสูตร
```

## 7. ความช่วยเหลือจากคน / การร่วมมือ

ได้ถามเพื่อน TA ผู้สอน หรือบุคคลอื่นเพื่อขอความช่วยเหลือในโจทย์นี้หรือไม่

```text
No
```

ถ้าใช่ ให้อธิบายสั้น ๆ ว่าได้รับความช่วยเหลือแบบใด

ตัวอย่างที่อนุญาต:

- อธิบายความหมายของโจทย์
- อธิบาย concept การเขียนโปรแกรม
- ให้ hint เกี่ยวกับแนวทาง
- คุยเรื่อง debugging
- คุยเรื่อง test cases
- ช่วยอธิบาย error message

สิ่งที่ไม่อนุญาต:

- คัดลอก code ของผู้อื่น
- ส่ง solution ของผู้อื่น
- ขอให้ผู้อื่นเขียน solution ให้
- ใช้ OJ submission ของผู้อื่น
- ขอให้ผู้อื่นส่ง OJ แทน
